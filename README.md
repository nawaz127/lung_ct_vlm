# Robustness and Explainability Evaluation of Lightweight CNNs for Lung CT Abnormality Classification

This repository contains a reproducible research pipeline for evaluating
lightweight convolutional neural networks (CNNs) on lung CT abnormality
classification under controlled image-quality degradation.

The target classes are:

- `Normal`
- `Benign`
- `Malignant`

The planned CNN study compares:

- MobileNetV3-Large
- EfficientNet-B0
- ResNet18

under:

- clean-baseline training
- corruption-aware training

with ImageNet initialization and three fixed random seeds per configuration.
The complete research matrix contains **18 CNN runs**. Frozen BiomedCLIP is a
separate supplementary zero-shot baseline; it is not a CNN training run.

> **Current status:** the software infrastructure through Sector 10 is
> implemented. The repository has not completed the 18 CNN research runs.
> Sector 10 is therefore `Tested`, not `Validated`. See
> [SECTOR_STATUS.md](SECTOR_STATUS.md) and
> [reports/audit/pre_training_readiness_audit.md](reports/audit/pre_training_readiness_audit.md).

## Important research limitations

- The dataset is split at the **image level**, not the patient or examination
  level. Patient/examination identifiers are unavailable.
- No expert lesion masks are available. XAI results measure attribution
  stability, not clinical localization or lesion-detection accuracy.
- BiomedCLIP is frozen and uses fixed prompts. It is a supplementary
  zero-shot baseline, not a fine-tuned CNN competitor.
- Only three random seeds are planned.
- The Sector 05 MobileNetV3-Large run is a two-epoch integration smoke test and
  must not be reported as a final research result.
- Do not fabricate missing metrics. Missing checkpoints and predictions must
  remain reported as missing.

## 1. Create and activate the Conda environment

Open **Anaconda Prompt** or PowerShell and run:

For a new environment using the repository file:

```powershell
conda env create -n torch_gpu -f environment.yml
conda activate torch_gpu
```

If `torch_gpu` already exists:

```powershell
conda activate torch_gpu
conda env update -n torch_gpu -f environment.yml
```

The `-n torch_gpu` option intentionally overrides the environment name stored
in the YAML file so the commands match the validated project environment.

If PowerShell reports that `conda` is not recognized, initialize Conda once
from Anaconda Prompt:

```powershell
conda init powershell
```

Close and reopen PowerShell, then activate the environment again. If a
PowerShell profile is blocked by execution policy, use Anaconda Prompt or run
the command in a PowerShell session with an appropriate user-level execution
policy approved by your administrator. Do not disable security controls
system-wide just to run this project.

Verify the environment:

```powershell
conda activate torch_gpu
python --version
python -c "import torch, torchvision; print(torch.__version__); print(torchvision.__version__); print(torch.cuda.is_available())"
```

If the environment file does not install the optional BiomedCLIP dependencies,
install the pinned packages:

```powershell
pip install open_clip_torch==2.23.0 transformers==4.35.2 "huggingface_hub>=0.19,<1"
```

## 3. Configure the dataset

The expected dataset structure is:

```text
data/raw/
├── Normal/
├── Bengin/       # historical spelling accepted as Benign
└── Malignant/
```

The `Bengin` directory is treated as the canonical `Benign` class alias. Do
not rename the source directory unless you also update the dataset
configuration and audit evidence.

The active dataset configuration is in
[configs/dataset.yaml](configs/dataset.yaml). It supports a local path or an
environment-variable override. The repository's validated data root is
`data/raw`.

Do not modify original images, manifests, or the test split during normal
pipeline execution.

## 4. Run the complete currently supported pipeline

The following sequence performs environment validation, dataset auditing,
manifest preparation, model checks, a short training smoke test, frozen
BiomedCLIP inference, evaluation, synthetic XAI validation, and final
completeness reporting.

It does **not** launch the 18-run research matrix.

### Step 4.1: Validate the environment

```powershell
python scripts/check_environment.py
```

This checks Python, PyTorch, CUDA, device selection, and basic runtime
configuration.

### Step 4.2: Audit the raw dataset

First perform a non-writing path check:

```powershell
python -m data.audit --config configs/dataset.yaml --dry-run
```

Then run the read-only dataset audit:

```powershell
python -m data.audit --config configs/dataset.yaml
```

Audit outputs are written to a timestamped directory under:

```text
reports/dataset_audit/
```

Validate a specific audit result when needed:

```powershell
python scripts/validate_dataset_audit.py
```

Use the generated `dataset_audit.json` path as the input to the split step.

### Step 4.3: Validate and generate manifests

Validation-only mode does not generate a new split:

```powershell
python -m data.preprocessing `
  --config configs/dataset.yaml `
  --preprocessing-config configs/preprocessing.yaml `
  --audit-json reports/dataset_audit/<audit-run>/dataset_audit.json `
  --validate-only
```

To generate the approved modeling manifests:

```powershell
python -m data.preprocessing `
  --config configs/dataset.yaml `
  --preprocessing-config configs/preprocessing.yaml `
  --audit-json reports/dataset_audit/<audit-run>/dataset_audit.json `
  --output-dir data/splits
```

The approved split policy is
`exclude_conflicted_groups`. The validated result contains:

| Split | Records |
|---|---:|
| Train | 1,347 |
| Validation | 288 |
| Test | 290 |
| Included total | 1,925 |
| Excluded cross-class duplicate records | 8 |

Expected output files:

```text

data/splits/test.csv
data/splits/combined.csv
data/splits/split_report.json
data/splits/split_report.md
data/splits/preprocessing_metadata.json
```

### Step 4.4: Inspect model availability

```powershell
python scripts/model_info.py
```

The model factory supports:

```text

```

ImageNet initialization is explicit. If a requested weight file is missing,
the factory must fail rather than silently switching to random initialization.
Do not download missing weights without explicit approval.

### Step 4.5: Run a training smoke test

The command below is an integration smoke test using only train and validation
manifests. It does not evaluate the test set:

```powershell
python scripts/train_model.py `
  --model mobilenet_v3_large `
  --initialization imagenet `
  --head-type gap_dropout_linear `
  --max-epochs 2 `
```

For a dry run:



Use a unique `--run-id` for every run. The current CLI does not enforce

### Step 4.6: Run frozen BiomedCLIP

## 5. Fixed configurations

### Preprocessing

Configured in [configs/preprocessing.yaml](configs/preprocessing.yaml):

- RGB conversion
- resize to `224 x 224`
- ImageNet normalization
- no validation/test augmentation
- stratified `70/15/15` split
- random seed `42`
- canonical mapping `Normal=0`, `Benign=1`, `Malignant=2`

### CNN training

Configured in [configs/training.yaml](configs/training.yaml):

- batch size `32`
- maximum epochs `20`
- DataLoader workers `0`
- AdamW
- learning rate `0.0001`
- weight decay `0.0001`
- unweighted cross-entropy
- ReduceLROnPlateau monitoring validation Macro-F1
- scheduler factor `0.5`
- scheduler patience `2`
- minimum learning rate `1e-6`
- early stopping patience `7`
- best and last checkpoints
- resume support
- CUDA FP16 AMP when CUDA is available

### Test corruptions

Configured in [configs/degradation.yaml](configs/degradation.yaml):

- clean
- Gaussian noise: standard deviations `0.03`, `0.08`, `0.15`
- Gaussian blur: sigma/kernel pairs `0.8/5`, `1.5/9`, `3.0/15`
- contrast reduction: factors `0.75`, `0.50`, `0.25`
- global seed `20261111`

These are frozen evaluation conditions. Do not change them to create a
corruption-aware training protocol.

### 7.2 Clean test Macro-F1

Values are mean ± sample standard deviation over the three seeds.

| Architecture | Clean baseline | Corruption-aware |
|---|---:|---:|
| MobileNetV3-Large | 0.9676 ± 0.0144 | **0.9793 ± 0.0034** |
| EfficientNet-B0 | 0.9733 ± 0.0126 | **0.9772 ± 0.0053** |
| ResNet18 | **0.9785 ± 0.0052** | 0.9783 ± 0.0018 |

The corruption-aware strategy improved clean Macro-F1 by mean paired
differences of `+0.0117` for MobileNetV3-Large, `+0.0039` for EfficientNet-B0,
and `-0.0002` for ResNet18.

### 7.3 Mean corrupted-condition Macro-F1

These means cover the nine corrupted conditions, averaged over the three
seeds.

| Architecture | Clean baseline | Corruption-aware | Paired improvement |
|---|---:|---:|---:|
| MobileNetV3-Large | 0.6489 ± 0.2867 | **0.8930 ± 0.1483** | +0.2441 |
| EfficientNet-B0 | 0.6251 ± 0.2399 | **0.8341 ± 0.2401** | +0.2089 |
| ResNet18 | 0.8248 ± 0.1415 | **0.9128 ± 0.0938** | +0.0880 |

Across all architecture/seed/corruption-condition pairs, the mean paired
corruption-aware minus clean-baseline difference was `+0.1804` Macro-F1.
These are descriptive paired differences, not claims of statistical
significance.

Across all CNN runs, the mean Macro-F1 by condition was:

| Condition | Mean Macro-F1 |
|---|---:|
| Clean | 0.9757 |
| Gaussian noise S1/S2/S3 | 0.7466 / 0.6798 / 0.5120 |
| Gaussian blur S1/S2/S3 | 0.8935 / 0.8113 / 0.6909 |
| Contrast reduction S1/S2/S3 | 0.9708 / 0.9642 / 0.8391 |

Gaussian noise, especially severity 3, was the most damaging condition in
this evaluation.

## 11. Troubleshooting

### `conda` is not recognized

Use Anaconda Prompt, or run `conda init powershell` once and reopen
PowerShell.

### `PYTHONPATH` import errors

From the repository root:

```powershell
$env:PYTHONPATH = "src"
```

### CUDA is unavailable

Run:

```powershell
python scripts/check_environment.py
```

For GPU-required smoke tests, keep `--require-cuda`; it is safer to stop than
to silently run a different protocol.

### Pretrained weights are missing

Do not allow the model to fall back to random initialization. Obtain the
official torchvision checkpoint only after approval, then rerun the model
construction check.

### Missing manifest images

Do not edit the manifest manually. Re-run the dataset audit and investigate
the configured `data/raw` path.

### Tests fail because of `.pytest_cache`

This is usually a Windows permission issue. The cache warning is non-fatal if
the tests themselves pass. Use a writable checkout directory if a clean test
environment is required.

## 12. Reproducibility and safety rules

- Never modify source images or historical manifests.
- Never use `test.csv` for training, tuning, or prompt selection.
- Never silently replace pretrained initialization with scratch initialization.
- Never overwrite historical experiment evidence.
- Never report fabricated or placeholder CNN results.
- Keep synthetic validation data separate from real research artifacts.
- Record configuration, software versions, hardware, manifests, and seeds.
- Keep the image-level split limitation visible in all final reports.
